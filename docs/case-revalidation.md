# 新版本产品案例复验准备

当前业务输入统一收口给用户。现有 15 条人工参考均为 draft，本机保存与改版轮均不覆盖旧参考和逐条报告，不统计业务验收通过率。控制塔继续整理证据和待决事项；缺失条件不阻塞已明确的技术链路。

## 新版输入与保留规则

- 用户提供新版本时，另存完整批次及版本说明，记录原文件哈希、修改字段、依据和确认人。实际客户事实、演示设定和待确认项分别标注。
- 延续已提供的稳定客户、需求、挂牌、交易及案例 ID，只有业务实体或独立需求确实新增才分配新 ID。原文与旧版本保留，不用新答案覆盖原 draft。
- 新版本需要明确六份需求的面积口径、精确户型或最低户型、近似面积语义、预算下限及费用范围、设施硬性程度、完整购买/入住日期。资料不足的字段继续 unknown，确认业务条件不等于批准公开来源或证明同屋身份。
- 真正缺失的数据由用户补充；仅用于展示的选择另记为演示设定。开发不根据人工预期修改过滤逻辑，也不替用户把参考改成 confirmed。

## 独立批次运行和报告

以下是**收到新版本以后**的命令示例，路径 `user-version-02` / `user-v02` 为示例名称，不表示该版本已经交付。准备输入必须仅含五张原始表、全部为 demo 且导入隔离数为零；不能混入仍待核验的 public-candidates。真实资料沿用原有导入与核验门槛。

```powershell
Set-Location E:\bhhs
node tools/prepare-demo-batch.mjs data/incoming/user-version-02/demo-prepared/dataset.json user-v02
$env:BHHS_DATA_DIR = 'data/demo/intake-local/user-v02/dataset.json'
$env:BHHS_API_PORT = '8002'
$env:BHHS_WEB_PORT = '5174'
npm run dev
```

先停止原批次服务，再在同一 5174 地址启动新版，默认 5173 主演示可保留。版本变化会使用独立的浏览器保存范围，旧副本不自动带入；切回原来源和原内容后，原副本仍可恢复。不要覆盖原运行副本来制造版本连续的假象。

在另一终端为新版本创建新的报告目录；如果目录已存在，改用新的名称：

```powershell
New-Item -ItemType Directory -Path data/incoming/user-version-02/revalidation-01 -ErrorAction Stop
node --import tsx tools/compare-match-references.mjs data/demo/intake-local/user-v02/dataset.json data/incoming/user-version-02/revalidation-01
```

工具输出 `candidate-comparison.json` 和 `候选对照报告.md`，内容是**该输入版本的人工参考与实际确定性结果对照**，案例数量取决于该版本。重复运行到相同目录会重生成这两份派生文件，因此每次正式复验用新目录。它不自动生成两个输入版本之间的差异，也不读取浏览器中的审核副本；需要比较浏览器审核结果时，先由用户把确认后的内容作为新版本输入交付。

改版房源库与助手采用 AED 搜索视图；原其他币种保留在来源和报告。命令行仍按输入全量挂牌及需求原币种核对，不暗中换汇。若新版本包含多币种，复验记录需说明界面范围与原输入范围，不能将范围差异当作匹配规则差异。演示 Sales ID 私有副本、看房记录和报告观察同样不进入该命令行对照。

收到新版后，以 `case_id` / `requirement_id` 对齐旧、新报告，另存版本差异表：字段及依据变化、旧/新候选 ID、目标的匹配/冲突/待澄清理由、人工参考状态、仍待补字段。引用各自输入哈希与实现提交 SHA；缺失或新增案例明确列出。旧报告和人工草稿始终保留。

## 复验记录口径

| 场景 | 实际操作及判定依据 |
|---|---|
| 可解释候选 | 应用对应版本需求，记录候选 ID；反向潜客展开同一需求，核对理由。若仍有未知文本，保留待审核状态 |
| 待澄清 | 缺面积口径、币种或原文冲突时提示具体项；零候选不能自动解释为市场上无房 |
| 当前样本与条件下无匹配 | 每个排除有独立字段依据；区别于信息不足，不以人工 no_match 标签自证 |
| 本机保存 | 审核为独立副本，刷新/重开后 ID、条件、正反向结果不变；原件可恢复、同客其他需求不丢失 |
| 价格与来源 | 挂牌价、同屋成交、可比成交分开，核对币种/面积口径与来源入口；无历史和单笔历史如实展示 |

每项记录版本、输入/实现证据、实际操作结果、未知项和用户确认范围。接收批次缺购买日期和多笔同屋成交时，继续用已有明确虚构的主演示验证日期排序和多笔图，不向接收资料补造记录。逐案内容与截图留在 `data/incoming/`、`data/private/` 或 `.work/`，不进入 Git。
