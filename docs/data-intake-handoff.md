# 已填数据模板的接收与交接

控制塔接收批次时，原件、逐行检查、来源引用和候选数据保存在 Git 忽略的 `data/incoming/` 或 `data/private/`，不提交进公开代码仓库。本文件只记录通用操作口径，不包含样本记录。

1. 留存原文件及 SHA-256，记录模板版本，核对五表英文表头、必填字段、公式/错误单元格、日期类型与跨表 ID。v1.0.0 与 v1.1.0 原件分别留存；旧 CSV/JSON 没有客户 area_basis 列可按兼容约定接收，不要求覆盖原件或推测补齐。
2. Excel 日期序列不携带时区。datetime 必须使用填写方提供的明确口径转换成带偏移的 ISO 8601；日期型字段保留原当地业务日期，不随意跨时区换日。只生成导入副本，原件不变。
3. 按 data_kind 分离真实资料候选和纯演示样例。真实核验与许可状态不得为了通过程序而修改；人工 draft 参考不等于业务验收基准。
4. 复用现有导入器进行技术预检，记录接收/隔离数、原 Excel 行号、原因和依赖影响。可明确推导的机械格式修正记录前后值；事实、规则及业务身份缺口交由产品核验。
5. 格式通过后，用现有筛选、匹配与价格函数对照人工预期；核对面积口径、日期缺失、约束理解、同屋/可比分类。技术通过与业务通过分别表述。
6. 在本地交接包内提供来源→处理→结果报告、分流 CSV/JSON、原件、转换清单及差异；公开仓库只留不含记录值的说明。

## 当前接入中的实现约定

- 用户已授权 v1.1.0 为客户需求新增选填 `area_basis`，位于 `area_unit` 后，枚举为 `internal/gross/built_up/land/unknown`。新明确字段优先；字段为空或旧记录无此字段时，兼容 `hard_constraints` 中已有英文面积口径，例如 `area basis: built_up`。旧 v1.0.0 schema、五表空 CSV、字典与契约保存在 `data/templates/v1.0.0/`，新版位于 `data/templates/v1.1.0/`；原 Excel 不覆盖。
- 字段与可解析原文存在不同口径时保留原值和证据，标记待确认，不静默覆盖原文或把冲突算作满足。显式 `unknown` 不算已知口径，也不自动使用文本或候选房源口径替代；缺失的客户口径不能从房源反向回填。面积单位换算不能代替口径核对。
- 接入预检需分别覆盖旧列缺失、新字段为空、明确口径、显式 unknown、字段与原文冲突及两种来源均缺失。契约与模板更新不代表导入、筛选和匹配已全部验收，实际结果另由开发验证记录。
- 自由文本中文条件不保证已被规则助手理解。重复的结构化描述与额外约束需核对，不能清空原条件来消除 Unknown。
- 路径加载器将 data/incoming 与 data/private 视为 product 模式。暂存在这些目录的 demo 准备副本，只做离线 demo 模式校验；运行时需使用独立 data/demo 子目录，并保留原演示基线。
- 公开构建继续由 export-public-demo.mjs 读取固定的纯演示快照。一次本地样本接收不授权自动发布、替换公开数据或上传用户输入。

接收批次本身不授权改写运行数据或业务规则。客户 area_basis 的本次授权增量需同时完成契约、模板、导入与匹配验证；具体完成状态以开发交接为准。开发收到批次后，按报告处理剩余输入，再执行相应场景验证并小步提交。
