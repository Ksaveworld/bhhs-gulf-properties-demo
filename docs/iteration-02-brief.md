## 开发可执行的交互说明

### 1. 房源下的客户名单

- 沿用“房源库 → 房源详情 → 潜在客户”入口，保留“一位客户 → 对应房源”的回跳。
- 首屏列出满足条件的客户；待补信息单独分组，硬条件冲突放入可展开区域。标签数量与实际展示口径一致，不把全部需求数写成适配客户人数。
- 按 client_id 统计人数，按 requirement_id 保留每份需求及其匹配解释；不可把不同需求的预算、区域等字段拼成一份虚构需求。
- 客户行优先展示：客户代称、预算区间、与本房报价的差额/是否满足、购房时间、具体意愿证据、冲突/缺口、建议下一步。
- 支持查看客户已有需求及相应房源。联系动作维持人工操作，不从录音推导 CRM 接入、自动触达或账号权限开发要求。

### 2. 评分与排序的产品口径

- 预算维度使用客户主动提供的预算，展示是否覆盖报价、币种和差额；不把预算上限当作真实资产或购买力证明。
- 意愿维度优先展示具体沟通事实。高/中/低及综合优先级的映射，需要产品 B 给出规则与正反例；资料不足显示待补。
- 可补充的两个参考维度：购房时间与房源可用时间是否相容、明确硬条件满足情况。它们作为解释，不擅自添加任意权重。
- 综合规则未确定时可先支持预算、时间及条件状态的透明排序，写清排序依据；不冒用“成交可能性”作为已验证概率。
- 若采用 0–100 演示分，应先确认规则并标明为规则分；不带百分号，不宣称成交预测准确率。演示分不能被写成真实业务评估。
- `match_reference` 是产品人工验收答案，不可直接拿来充当系统预测结果。人工参考如需展示必须说明其来源与性质。

### 3. 成交时间线与曲线

- 放在现有价格证据页，同一套房的合格成交记录按时间排序，显示成交日期、金额、币种、来源及“收录成交 N 笔”。N 按唯一交易记录计数，不宣称覆盖该房产全部历史。
- 默认展示全部可用历史；时间范围控件按数据跨度提供。图二的 30/60/180 天可作交互参考，不作为已冻结的筛选要求。
- 横轴是实际成交日期，纵轴明确总价及币种；如切换单价，须明确面积单位与口径。不同币种、合同日与登记日口径不能无说明混用。
- 0 条记录显示无可用历史；1 条显示单点与记录；多条可用成交点和直线连接，标明连线仅便于阅读。悬停或点击可查看日期、价格和对应来源。
- 不做平滑拟合或每日价格补齐。历史跨度中没有成交的日期，不能据连线当作有真实市场报价。
- 同屋历史、挂牌价格变化、周边可比成交保持分开；可比房屋的交易不能串进本屋历史。当前挂牌价如用于比较，应单独标注。
- 图二那种高频阶梯形走势更适合有连续采集依据的挂牌报价变化；若后续需要，使用 `listing_snapshots` 的采集时间与报价单独展示，不复用为成交走势。

真实资料沿用授权脱敏、来源核验和使用许可要求；缺失资料继续留空。无需让产品重填全部模板，优先补本轮涉及的记录与规则。

## 本轮验收建议

1. 从同一房源看到适配客户与原因，并能回到该客户的候选房源；切换房源后名单和人数正确更新。
2. 同一客户多份需求不会增加客户人数，冲突客户不会计入适配人数；每个判断可追溯到相应需求。
3. 排序项与实际顺序一致，预算、意愿和时间未知时有明确状态，不输出无依据的高分或百分比。
4. 成交图的日期、金额、笔数与明细一致；点击点能找到原记录及来源；0/1/多条记录与空时间范围均可用。
5. 可比交易、挂牌快照和不合格交易均不会进入同屋成交曲线；货币与日期口径有明确处理。
6. 原有筛选、需求审核、双向匹配、价格证据资格校验继续有效。按本次影响范围验证，不用截图替代交互核验。

## 给开发窗口的补充提示词

在当前 BHHS Demo 上做第二轮增量，先读本文件与 AGENTS.md。保留已实现的主链路，集中完善房源下客户名单、可解释排序、同屋成交时间线和价格曲线。优先完成不依赖评分权重的交互；新增评分规则、房源销售归属字段及真实数据缺口向控制塔列明，不自行视为已确认。

不要把人工验收答案当成模型输出，不生成无依据的成交百分比，不将可比成交或挂牌快照混入同屋历史。沿用现有英文界面和品牌样式；用户截图没有提出全站改版、中文化或重做详情页的要求。

按“客户名单与计数 → 透明排序 → 成交可视化 → 验证与交接”拆成可独立检查的提交。每笔提交记录 Changes、Validation、必要时 Remaining；交接给出 SHA、实际验证、未完成产品输入。提交前检查工作区及暂存范围，保留其他任务改动，不自动 push 或部署。
