# 需求的本机保存

销售以 Username / Sales ID 演示登录后，可以创建私有客户或保存已有需求的新版本。页面确认写入并回读成功后才关闭表单并显示 **Saved in this browser**，含义为“已保存到当前浏览器”。原始导入需求、Excel、批次 JSON/CSV 和人工参考不被写回。Sales ID 仅用于演示分区，不具备正式认证能力。

## 使用方式

1. **Home** 提供 **Find a Property**、**Find a Client**、**Create a Private Client**。发送自然语言后自动填入对应复核表单。前两项点击 **Continue** 直接带条件进入列表，不创建客户或持久化需求；未提交的输入和临时筛选不属于已保存副本。
2. **Create a Private Client** 必须补齐核心字段，再点击 **Continue** 进入完整字段确认表。**Back / Edit** 返回修改，**Confirm & Create** 才写入当前 Sales ID 的私有客户。V3 的 **Clients & needs → Add Private Client** 在当前页内复用此流程；访客可以准备草稿，再选择销售身份，身份选择不会丢掉审核表。创建成功后打开新客户的 **Client Details → Recommended Properties**。
3. 在客户详情点击 **Edit Current Needs**，通过 **Save requirements** 保存完整新版本，沿用客户 ID，并显式关联被编辑的父版本。当前视图与匹配使用该版本，父版本仍保留在 **Requirement History**。历史展示更新日期、增加/修改/取消的条件及各版本内容。未提交即关闭编辑器不会保存草稿。
4. 同一客户已有的独立购房方案、旧格式独立副本不会因为客户 ID 相同就自动合并。详情中的 **Independent plan** 切换方案；每个显式修订链分别选择当前版本，不跨方案拼接预算、地区或其他条件。历史原件继续保留，不依据人工参考答案改规则。
5. **Delete local copy** 只删除选中的本地版本。删除当前修订后，仍保留的父版本重新成为该方案当前版本；删除独立新建需求则移除该份需求。**Restore original** 将最初导入的条件追加为新的修订，并保留此前修订历史；它不再通过删除当前副本完成恢复。没有导入原件的新需求只提供删除。删除父副本不连带删除后续副本，缺失的父节点保留追溯 ID。
6. 刷新页面、点击 **Refresh data**、关闭后重开同一浏览器配置中的同一地址、批次版本及 Sales ID，能够重新读取副本。有效地址中的客户/房源 ID 恢复对应详情；临时筛选、独立方案的临时选择及未保存草稿不作为持久化承诺。
7. 保存、删除或读取失败时显示错误；保存失败保留打开的表单和已填内容，不报告成功。解除浏览器限制后可重试；无法读取本地存储时，导入需求仍可查看。回读失败表示无法确认是否写入，界面不会以成功状态掩盖这种情况。

V3 详情之间连续查看不会切换主页面；关闭当前详情回到上一层，保留其页签和独立方案。一次会话中的父层草稿可保留，但不扩大刷新后恢复的承诺。日期使用英文 ISO 输入提示，购房日期仍是纯日期，看房记录仍按本机时间转为 UTC 存储。

**保存不等于业务确认。** 副本继续为 `needs_review`，原文、未识别或矛盾条件、缺面积口径和待补信息仍参与提示。修改后的数值与原文不一致时继续保留待澄清问题。没有确认依据时口径保持 unknown；不从候选房源反填，不改变人工参考的 draft 状态。Home 新建表单固定 AED / sq ft；非 AED 预算须重新确认，面积单位换算不提供面积口径。编辑已有需求保留其原币种和单位，不把 USD 金额直接改标为 AED。

## 保存范围

本机保存使用浏览器 `localStorage`，同时按网站地址、数据来源、内容版本和 Sales ID 隔离。公司导入演示需求对各演示身份可见；新建私客及公司需求的本地修订仅存放在创建者身份的浏览器范围。

**副本的私有可见范围与客户归属类型是两件事。** 公司客户的本地修订仍属于 Company，`sales_owner` 沿用导入原件，不改成当前编辑者。其他销售继续看到自己的当前版本或公司原件。导入记录对归属有分歧时显示待确认，不自动指定跟进人。**Unassigned** 指导入公司客户尚未分配销售，不代表旧浏览器副本。

原先没有身份的浏览器副本仍在原键中，退出演示身份后通过 **Clients & needs → Local data notes → Review legacy local copies** 查看。没有把它们自动分配给第一位登录销售，也没有删除旧记录。新副本追加 `:sales:<SalesID>` 到原批次键，结构版本仍为 1。Sales ID 区分大小写；切换身份时清除旧详情和选择，客户目录、推荐、反向潜客、看房记录与上下文导出使用当前身份可见的数据。

| 范围变化 | 行为 |
|---|---|
| 同一地址、来源、Sales ID，五张原始表内容不变 | 恢复已保存副本；只更新加载时间不新建版本 |
| 同一地址切换数据目录或内容版本 | 显示该版本自己的副本，不迁移旧版本需求 |
| 返回原来源和原版本 | 可再次读取该版本仍保存的副本 |
| 切换 Sales ID / 退出登录 | 只读取该身份的副本；退出后可从 Local data notes 查看旧无身份副本，保存内容不删除 |
| 改用另一个端口、localhost/127.0.0.1、浏览器配置或设备 | 属于不同存储范围，不自动共享 |
| 清除网站数据或结束隐私浏览 | 副本可能被浏览器删除；没有服务器备份 |

来源由 API 的内部 `meta.storage_namespace` 标记，使用来源路径与模式的摘要，不返回本机绝对路径。浏览器对该标记、模式及五张导入表计算 SHA-256 版本键。`loaded_at`、显示名称和提示不参与版本键；对象 key 顺序不影响键，数组行顺序改变会保守地视为新版本。本地副本不参与版本键。

兼容旧输入时，新增的可选 `area_max` 缺失或为 null 不改变旧批次键；提供具体面积上限则参与版本计算。旧无 `edit_kind` 的副本仍按独立方案读取，不被追认成新版本链。

因此，新版数据即使只是修改人工参考，也不会自动继承旧版浏览器需求。旧副本留在原版本范围内，不能据此把旧审核意见套用到新输入。此处是本机保存的隔离策略，不是新增业务规则。

## 技术交接

持久化容器版本为 `1`；浏览器修订关系与产品 CSV/Excel 业务字段分开：

| 字段 | 用途 |
|---|---|
| `version`、`key`、`revision` | 存储格式、来源/内容版本键、写入修订号 |
| `copies[].requirement` | 完整需求记录，含新的需求 ID 及可选 `area_max` |
| `original_requirement_id` | 最初导入的需求 ID；从零新增时为 null |
| `parent_requirement_id` | 本次审核所依据的需求或副本 ID；父副本删除后保留追溯 ID |
| `edit_kind` | 新的显式编辑为 `revision`，在当前视图替代其父版本；旧副本缺失此字段时保留独立方案语义 |
| `saved_at` | 浏览器保存时间，不充当客户购买日期或来源时间 |

读取会校验格式、字段、ID 和关联关系；损坏内容不会被当成空存储直接覆盖。写入前校验修订号，写入后回读一致才成功。页面响应同源存储变更；支持 Web Locks 的浏览器串行执行本应用写入。不支持时使用修订号检查，不承诺跨标签原子事务。

原件与副本使用同一套 `requirementsToFilters`、`filterListings` 和 `evaluateMatch`；匹配前先按显式修订关系投影各方案当前版本。浏览器副本不出现在只读 API 或命令行批次对照报告中。新版案例复验见 [复验准备](case-revalidation.md)，当前执行证据见 [开发交接](dev-handoff.md)。

## 演示设定记录

没有新增已确认的客户业务事实。浏览器回归使用仓库内明确虚构的预算、日期及同客多需求用例；存储失败通过测试注入模拟。本机保存轮的实际接收批次重开验证仅在隔离 QA 浏览器副本上暂选 `built_up`，用于观察保存和匹配是否一致；该选择不是客户事实或用户确认。该轮结束已恢复原件并确认副本删除，原批次未知口径、未知日期和草稿保持原状。逐条 QA 记录留在忽略目录。

改版采用的演示设定包括：原始导入样本视为公司共享、新建客户归当前 Sales ID；公司客户的本地修订仅对编辑者显示，但公司归属不变。这些演示分区不是对真实输入权限的确认。历史报告用例曾在隔离的 B/C 浏览器副本中补测试预算下限，原件不变；该设定不建立新的业务阈值。当前看房与上下文导出方式见 [报告记录](report-records.md)。
