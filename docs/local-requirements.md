# 需求的本机保存

销售先以 Username / Sales ID 演示登录，点击 **Apply to property library** 后，新增需求或审核结果保存为当前浏览器中属于该 Sales ID 的独立私有副本。页面确认写入并回读成功后才关闭表单、应用筛选并显示 **Saved in this browser · 已保存到当前浏览器**。原始导入需求、Excel、批次 JSON/CSV 和人工参考不被写回。该身份不具备正式认证能力。

## 使用方式

1. 在 **Home** 的需求模块或 **Clients & needs → Add Private Client** 新增需求，或选中需求后点击 **Review selected requirement**。应用前显示 **Not saved**；关闭未应用的表单不会保存草稿。
2. 应用后可在 **Clients & needs** 或客户下拉框找到副本。刷新页面、点击 **Refresh data**、关闭后重开同一浏览器配置中的同一地址及 Sales ID，都能恢复副本。有效地址中的需求/房源 ID 会恢复上下文，临时手动筛选重置，不删除副本。
3. 再次审核副本会生成另一份独立需求，沿用客户 ID；不会替换原件或上一份副本。同一客户的不同需求分别参与候选和反向潜客评估。
4. **Delete local copy** 只删除选中的副本。**Restore original** 删除当前副本并切回其最初导入的需求，其他副本保留。新建需求没有导入原件，因此只提供删除。删除父副本不会连带删除后续副本。
5. 保存、删除或读取失败时显示错误；保存失败保留打开的表单和已填内容，不报告成功。解除浏览器限制后可重试；无法读取本地存储时，导入需求仍可查看。回读失败表示无法确认是否写入，界面不会以成功状态掩盖这种情况。

**保存不等于业务确认。** 副本继续为 `needs_review`，原文、未识别或矛盾条件、缺面积口径和待补信息仍参与提示。没有确认依据时口径保持 unknown；不从候选房源反填，不改变人工参考的 draft 状态。

## 保存范围

本机保存使用浏览器 `localStorage`，同时按网站地址、数据来源、内容版本和 Sales ID 隔离。公司导入演示需求对各演示身份可见；新建客户与公司需求的本地审核副本仅对其创建者身份显示。

原先没有身份的浏览器副本仍在原键中，退出演示身份后通过 **Unassigned browser review** 查看。没有把它们自动分配给第一位登录销售，也没有删除旧记录。新副本追加 `:sales:<SalesID>` 到原批次键，结构版本仍为 1。Sales ID 区分大小写；切换身份时同步清除旧详情和选择，客户目录、候选下拉、潜客和 Reports 使用当前身份可见的需求。

| 范围变化 | 行为 |
|---|---|
| 同一地址、来源、Sales ID，五张原始表内容不变 | 恢复已保存副本；只更新加载时间不新建版本 |
| 同一地址切换数据目录或内容版本 | 显示该版本自己的副本，不迁移旧版本需求 |
| 返回原来源和原版本 | 可再次读取该版本仍保存的副本 |
| 切换 Sales ID / 退出登录 | 只显示该身份的副本 / 退出后显示旧无归属副本，保存内容不删除 |
| 改用另一个端口、localhost/127.0.0.1、浏览器配置或设备 | 属于不同存储范围，不自动共享 |
| 清除网站数据或结束隐私浏览 | 副本可能被浏览器删除；没有服务器备份 |

来源由 API 的内部 `meta.storage_namespace` 标记，使用来源路径与模式的摘要，不返回本机绝对路径。浏览器对该标记、模式及五张导入表计算 SHA-256 版本键。`loaded_at`、显示名称和提示不参与版本键；对象 key 顺序不影响键，数组行顺序改变会保守地视为新版本。本地副本不参与版本键。

因此，新版数据即使只是修改人工参考，也不会自动继承旧版浏览器需求。旧副本留在原版本范围内，不能据此把旧审核意见套用到新输入。此处是本机保存的隔离策略，不是新增业务规则。

## 技术交接

持久化结构版本为 `1`，不改变产品 CSV/Excel 契约：

| 字段 | 用途 |
|---|---|
| `version`、`key`、`revision` | 存储格式、来源/内容版本键、写入修订号 |
| `copies[].requirement` | 使用原有需求类型的独立记录，含新的需求 ID |
| `original_requirement_id` | 最初导入的需求 ID；从零新增时为 null |
| `parent_requirement_id` | 本次审核所依据的需求或副本 ID；父副本删除后保留追溯 ID |
| `saved_at` | 浏览器保存时间，不充当客户购买日期或来源时间 |

读取会校验格式、字段、ID 和关联关系；损坏内容不会被当成空存储直接覆盖。写入前校验修订号，写入后回读一致才成功。页面响应同源存储变更；支持 Web Locks 的浏览器串行执行本应用写入。不支持时使用修订号检查，不承诺跨标签原子事务。

原件与副本使用同一套 `requirementsToFilters`、`filterListings` 和 `evaluateMatch`。浏览器副本不出现在只读 API 或命令行批次对照报告中。新版案例复验见 [复验准备](case-revalidation.md)，当前执行证据见 [开发交接](dev-handoff.md)。

## 演示设定记录

没有新增已确认的客户业务事实。浏览器回归使用仓库内明确虚构的预算、日期及同客多需求用例；存储失败通过测试注入模拟。本机保存轮的实际接收批次重开验证仅在隔离 QA 浏览器副本上暂选 `built_up`，用于观察保存和匹配是否一致；该选择不是客户事实或用户确认。该轮结束已恢复原件并确认副本删除，原批次未知口径、未知日期和草稿保持原状。逐条 QA 记录留在忽略目录。

改版采用的演示设定包括：原始导入样本视为公司共享、浏览器新增/审核视为当前 Sales ID 私有。它们不是对真实输入权限的确认。报告正向分支验证只在隔离的 B/C 浏览器副本中补测试预算下限，原件不变；客群样本阈值及虚构看房详见 [报告记录](report-records.md)。
