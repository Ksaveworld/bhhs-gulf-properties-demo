# 客户原文与结构化条件核对

审核使用客户需求的 `raw_request`、`hard_constraints` 和结构字段，不读取 `match_reference` 推导规则或推荐。所有原文保留；同一客户的页面审核生成新的会话需求，原输入仍可回看。页面重载后会话修改清除，不写回文件。

## 面积口径

v1.1.0 客户 `area_basis` 是选填字段，枚举与房源一致。明确字段优先；为空或缺列时回退到 v1 的 `area basis: built_up/internal/gross/land` 文本。显式 `unknown` 不回退。多个旧口径或字段与旧口径冲突时，表单保留优先字段供审核，实际比较口径为 unknown，提示“面积口径待确认”。

面积单位只支持换算数值，不解释口径。缺口径、缺单位或口径不同不能确认为面积满足。助手只承接明确的口径表达；含糊中文、否定、多口径或单纯物业类型不自动选定口径。没有产品依据时不从候选房源补齐。

## 中文硬条件

完整句段同时满足下列要求，才标为“已由结构字段表达”，并显示对应 key；文字仍保留在硬条件框。

- 明确预算上限：币种、金额完全一致，且 `budget_constraint=hard`。附加费用、上浮、不同币种或硬性程度不明继续提示。
- 明确“至少／不少于／不低于／不小于”的卧室或面积下限：数值一致；面积单位也必须一致。完整“至少 N 居和 M sqft”可对应两个下限，但不证明面积口径。
- 单写“现房／期房”或“必须／只考虑”市场条件位于硬条件中时，与结构选择核对并保留其硬性属性。
- 明确的设施组合可作为硬条件，例如“需要花园和停车位”；否定、选择关系和剩余未识别文字不转为正向满足。

裸写“3 居”、正好、最多、约、跨币种／跨单位和额外限制，不被吞成下限重复。原文中可解析的预算、卧室、面积矛盾，以及“需要”设施只出现在偏好等情况，会在审核表单、候选库和房源的客户解释中提示。

原文只有明确预算上限而结构字段另填 `budget_min` 时，提示下限依据待确认。程序保留该值和原文，不擅自删除下限或认定它来自客户；销售需核对补充证据后再应用。

“可接受期房”不表示只接受期房；只有明示现房期房均可才填 `either`。“偏好期房”可以用于销售主动选择的搜索过滤，但不是硬排除证据；双向解释将其视为偏好差异。相对购房／入住时间不补造完整日期。

## 结果含义

房源库数量是使用结构字段的候选数，未知文本仍可保留待核对候选。未知／矛盾不会被宣称为“条件满足”：库中显示 `Review details`，并明确这些不是已确认推荐；房源详情列出原因。面积条件口径未确认导致 0 候选时，单独显示面积比较待确认，不宣称业务上无房可选。

本轮规则仅覆盖有明确语法的条件，不是通用自然语言理解，也不把产品 draft 草稿转为已确认业务标准。需要产品 B 逐项确认缺口径、裸户型、预算上下限依据、硬条件与偏好、费用和完整日期。
