# 开发窗口补充指令：Git 留痕与数据模板

请继续执行已交接的 BHHS Demo 主链路，并遵守项目根目录 `AGENTS.md`。

## 开发过程必须小步 commit

用户已明确授权本地提交。每完成一个可独立验证的改动就提交，不等整个 Demo 做完才一次提交。提交按功能或修复拆分；不要每保存一次文件就提交。

1. 开工检查分支、最近提交和工作区状态，保留他人改动。
2. 完成本次改动后，运行相应验证并检查差异。
3. 只暂存本次明确负责的文件；检查暂存文件清单和内容。
4. 提交标题说明具体变化，正文写 Changes、Validation、必要时 Remaining。失败/未验证项目如实记录。
5. 提交后核对 SHA、文件清单和剩余改动；阶段汇报中附短 SHA 和实际验证结果。
6. 交接前完成本次合理的小步提交，保留历史。不自动 push，不改写旧提交。

## 数据接口与当前责任

数据模板及说明由控制塔提供。开发先读 `docs/data-contract.md` 与 `data/templates/schema.json`；以 CSV 的英文表头作为字段 key，Excel 的中文表头仅帮助产品填写。

- 用户现已决定单人推进。原产品 A 的三张房源/成交表、产品 B 的需求/人工参考表由控制塔协助核对，集中向用户交付建议和剩余问题；不再分发给两位产品等待反馈。
- 资料缺失时列缺口，使用明确标注的演示样例推进不受影响的交互。不能编造真实证据；用户确定的演示假设另存版本，原始样本和人工 draft 保留。
- 当前契约为 v1.1.0，保留 v1 兼容。模板版本不是业务规则已冻结的证明；修改共享字段前向控制塔说明影响，不静默改名或改变语义。
- 真实填写文件存 `data/incoming/` 或 `data/private/`。不要用实际客户资料覆盖、提交空白模板。

本轮执行范围和验收见 `docs/solo-execution-brief.md`。

## 每次交接至少报告

- 当前分支、最后一个提交短 SHA。
- 已完成的功能及其对应提交。
- 实际执行的验证、结果及未验证范围。
- 工作区是否有未提交修改，归属是谁。
- 尚缺的产品数据/规则和需控制塔处理的问题。
- 本地启动方式、访问地址；仍属演示的内容。
